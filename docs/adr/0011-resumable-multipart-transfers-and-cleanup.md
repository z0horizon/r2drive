# 0011: Resumable Multipart Transfers and Automated Stale Upload Cleanup

Leverage `r2kit`'s native snapshot and resume primitives (`MultipartSessionSnapshot`, `Bucket::resume_managed_multipart`, `Bucket::resume_presigned_multipart`) to provide fault-tolerant, resumable uploads across both the CLI and WebConsole. The CLI persists session snapshots to a local cache directory (`~/.cache/r2drive/uploads/`), while the WebConsole persists active transfer manifests in browser `IndexedDB` backed by a `multipart_sessions` table in `MetadataStore`. In-flight network drops trigger automatic exponential backoff retries, while user reloads offer seamless resumption upon re-selecting the source file. To prevent orphaned parts from incurring Cloudflare R2 storage fees, manual cancel actions trigger instant aborts, supplemented by a daily automated cleanup worker that aborts sessions inactive for more than 24 hours.
